# Core BC retry concurrency, operations version 2

The user authorized 16 concurrent trajectories per harness × strategy cell. This changes scheduling only: the fixed 963-job retry selection, question/repeat identities, assigned provider routes, scientific configuration, native workers, existing claims and attempts stay unchanged.

`set_bc_retry1_concurrency_ops2.py` publishes the already-supported mutable dispatch policy. It first verifies ten fresh, distinct cloud cell controllers and the idle local controller, original frozen source/input hashes, and exact controller identities. It temporarily requests zero new dispatch and waits for matching policy SHA acknowledgements. It does **not** signal or wait for existing paid trajectories to finish. It then publishes `cloud-dispatch-retry1-ops2.json`: cloud total target 16, original Huoshan route cap 16, SFB route cap 16, both SFC routes disabled, local dispatch zero. The total cap remains 16 even when both allowed routes have available work. Disabling the idle local dispatcher prevents additional local jobs from exceeding a cloud cell's target.

Existing controllers keep their live child maps and the same atomic claims/slot ownership, avoiding restart or duplicate admission. The script records the original, pause and enabled policy bytes, all SHAs, exact controller identities and acknowledgements under `outputs/campaigns/bc100-r3-hermes-parity-v3-retry1/operations/bc-retry1-hot-concurrency-ops2/`. A prior cutover marker prevents automatic replay. Failure leaves an explicit error receipt and requires inspection; it never retries a prediction.

Run `python scripts/set_bc_retry1_concurrency_ops2.py` for a zero-model-call dry run. The authorized deployment uses `--live --ack-timeout 300`; the longer acknowledgement deadline allows cloud controllers to publish their status after admitting new children. Frozen scientific inputs are checked again before enabling dispatch. Three targeted tests cover total versus route caps, exact identity/policy acknowledgements, and atomic byte publication.

Targets are not measured concurrency. Controller `active_local` counts supervised trajectories; node telemetry separately reports live native worker and OS-process counts. Completion rate, provider errors and unknown token usage continue to be recorded by the existing monitors. The new user authorization supersedes the earlier global 128-process planning limit; actual OS processes and actual model trajectories must still be reported separately. No route is reassigned and no failed prediction gains another attempt through this change.
