# Controlled native-image continuation, v3

This version performs one controlled compression of a fixed, real trajectory prefix, followed by the actual Hermes tool loop. It is not the original full-trajectory experiment with repeated compression at a 32k trigger. The previous two 1800-second capture failures remain separate, unchanged results.

The pilot uses the same two originally selected questions. The first archived request with measured provider prompt usage at least 16,384 is selected independently of correctness; its full native image payloads and detail settings are preserved. Prefix selection never uses reference answers, successful completion or a preferred token ranking. Initial native input is not resized or deleted to make a budget pass. Each subsequent arm retains its own new tool evidence. This is a paired initial-prefix intervention, not a claim that diverging future tool results are identical across arms.

The visual arm first validates the common 16,384 input ceiling and returns the first actual continuation prompt usage. V3 uses that measurement as the shared target after checking the prefix SHA256 and original native-image ledger. Each arm must fit within 2% of this target and within the common ceiling; the queue independently checks the three-arm realized spread is at most 5%. Native-only input exceeding the target is explicitly infeasible. Missing provider usage is not a passed gate.

Sliding Window fits a suffix of the same text history using at most ten measured binary-search probes. Summarization generates a substantive summary preserving source-backed facts, then adjusts requested length based on measured usage, with at most four attempts. No padding, repeated filler, invented detail or altered native pixels is permitted. A truncated/empty summary or exhausted fitting attempts remains a recorded failure. Visual replay, if needed, uses the original target representation unchanged. The first actual agent call is measured again; missing or out-of-range usage immediately aborts further calls rather than continuing on an assumed budget.

Budget probes and every summarization attempt have separate `budget_calibration` / `compaction` purposes in the same raw metrics ledger. Their costs are retained even on failure. They can warm provider caches: subsequent cache-hit rates are observational rates for this calibrated protocol, **not production cache-hit rates**. Report auxiliary costs, first actual post-compression call, and continuation totals separately. Complete end-to-end cost is the declared shared prefix acquisition expenditure plus calibration and continuation; do not silently count archived prefix acquisition as free or multiply its shared cost without stating the allocation rule. Image token splits, provider-internal latency and actual dollars remain unknown when not supplied by the provider/tariff.

The live queue starts with the paired pilot, then expands the fixed question/repeat plan only when the control gates pass. The upper bound is 16 supplementary workers, with actual concurrency limited by shared process admission below 128 visible processes and priority for the core BC 16. Missing/failing questions remain in the declared cohort; no easier replacement question is selected. AgenticDataBench remains blocked until its actual tool sandbox is available.

Validation: `scripts/check_controlled_native_v3.py` ran a local server and the real Hermes tool loop for the visual reference plus all three V3 methods. Every arm performed web search and a second agent request containing the resulting tool evidence, then returned a final answer. All target/native gates passed; zero paid requests. Artifact: `outputs/preflight/controlled-native-v3-1794053136548145046/result.json`. The V2 composition tests also verify preservation of native bytes/detail, unchanged later tool messages, and rejection of unfrozen URL-only image evidence.

Files: `controlled_native_worker_v2.py` supplies the visual reference; `controlled_native_worker_v3.py` performs matched continuation. Both retain worker leases and started markers, so a partially executed attempt is not silently reissued. Runtime specs and implementation hashes must be frozen before dispatch; fixes use a new explicit version/attempt and preserve earlier incurred usage.
