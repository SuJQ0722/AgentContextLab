# Controlled native-image continuation v4

This is a separately versioned, fixed-prefix, single-intervention experiment. It is **not** a completed three-benchmark reproduction or the original 32k-trigger, repeatedly compressed full-trajectory study. The fixed cohort is the first ten previously frozen questions of BrowseComp-V3 and MMBrowseComp, three repeats, three arms (180 continuations). AgenticDataBench remains blocked by its unavailable task sandbox; web-only tools cannot substitute for that environment.

Each question/repeat has one shared prefix, selected at the first provider-measured input of at least 16,384 tokens, independently of correctness. Two historical pilot prefixes are reused without their subsequent answer responses. Their original route is recorded separately from the new continuation route: `deepseek-v4.1-flash-1017/zijian/sfb`. All three new arms use that same route. Historical acquisition through the selected call is retained once in `historical-prefix-acquisition.json`; new collection costs are also counted once, not three times.

All original inline native image bytes and detail settings are retained, in the same common order across arms. Only archived text changes representation: a PDF-rendered canvas, a substantive summary, or a suffix text window. VERA renders text at font16; the predeclared canvas scale sequence is 1, .75, .5, .25, selecting the first provider-measured prompt that fits16,384. Those scales never change original native images. The actual first VERA continuation establishes the target; summary and window must each fit within2%, and the three-arm spread must remain at most5%. A common ceiling alone does not pass this gate. Missing prompt usage, over-budget native evidence, or inability to fit without padding remain explicit failures. Provider-specific image-token counts are unknown unless separately returned; identical bytes are not presented as a measured image-token split.

Summary generation receives a separate system instruction and an explicitly encoded archive. It must return substantive source-supported JSON prose; DSML/function-call markup, tool calls, empty/truncated output, and base64 are rejected. Up to four generations and ten suffix-window measurements are allowed; every attempt is charged to its purpose. The continuation uses the real Hermes loop with `web_search`, `web_extract`, `image_search`, `image_crop`, and `image_zoom_in`. Caption/vision-analysis auxiliary calls are forbidden. The reviewed endpoint/model guard remains active, and a new observer compares every SDK image ledger with the final HTTP request without inserting or changing images.

Budget validity and task outcome are separate. A timed-out continuation can provide valid first-request budget evidence; that timeout remains in the accuracy denominator and is never relabeled completed. Conversely a completed answer does not make missing budget evidence valid. The six-arm pilot must pass the budget/native gate before the remaining fixed cohort is dispatched. No failed question is swapped for an easier one. This experiment performs one compression intervention; later continuation history is not recompressed.

All raw provider usage, failures, started-without-returned-usage records, and known subtotals are retained. Cached input is never inferred from absence; non-cache input is derived only when prompt and cache counts are both known for the same call. API timing means SDK client duration including retries/streaming, not provider-internal latency. Rendering time is separate. Summary and fitting calls are separate purposes, and fitting warms caches: their observed cache rate is not an untreated production cache rate. Dollar cost and provider image tokens remain unknown rather than using Gemini pricing.

Run or resume the already prepared version with:

```sh
python scripts/run_controlled_native_v4.py --resume --live
```

Outputs: `outputs/experiment3/controlled-native-v4`. Permanent per-worker and dispatcher markers prevent automatic retries of terminal or unknown paid attempts. Scientific/core campaign sources and historical v2/v3 outputs are unchanged. The supplemental admission helper shares the existing lock/ledger, reserves two local core tasks, requires fewer than128 visible local processes, and limits this queue to four concurrent slots. Actual dispatch can be lower when capacity is unavailable.

Validation: five targeted unit tests cover invalid summaries, missing/cache-zero usage, budget-versus-timeout gates, preservation of subsequent tool messages, and current local-core reservation. The localhost fixture in `outputs/preflight/controlled-native-v4-1794199626306477501/result.json` ran all three arms through the actual Hermes loop, real PDF rendering and final HTTP payload inspection, with two agent requests and an intervening web search per arm. It made zero paid calls. Before launch, local Reader `/health` returned200 and the real search/fetch provider preflight returned nonempty evidence.
