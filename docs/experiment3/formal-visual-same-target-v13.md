# Nine formal visual continuations: prepared, not authorized

The fourteen formal V8 visual units already used six attempts each. They cannot be relaunched under the new cumulative three-attempt allowance. A separate extra-attempt authorization is required. Of these fourteen, nine have a certified historical target; five have no provider-measured first continuation usage and are excluded from this prepared plan.

`scripts/controlled_visual_same_target_v13.py` prepares the nine-target subset. It replays the exact historical representation and original native evidence, including original lossless WebP bytes, not newly encoded substitutes. The offline audit checks decoded RGBA equality against the saved PNG and matches each final HTTP image's byte SHA, detail and order against an actual historical wire ledger. All nine pass this image audit and the original V8 validation.

The V8 protocol is preserved: separate 1024×1536 pages at font16, original base scale .75 times the originally selected fit scale, at most ten total images and a 32 MiB request limit, older text pages removed first when needed, every native image retained unchanged and placed last, inline upload without image hosting. This is **not** the newer RQ3 seven-page protocol. No rerendering, scale refitting, native deletion, or target replacement is permitted by this worker.

Before a real continuation, its provider-measured calibration prompt must be within ±2% of the immutable target and <=16384. The first actual agent response ledger, including a failed stream with usage, must satisfy the same bound. Missing usage fails closed. Later continuation growth is not constrained to the first-turn target. Three-arm comparisons still require the independent <=5% group spread gate and the same question/repeat/prefix/native identities. The explicit new 500-round, 3600-second execution allowance must be reported separately from the earlier 60-round results.

The entrypoint defaults to zero-paid behavior. `--live` also requires an authorization file with `authorized: true`, the exact prepared plan SHA, `additional_attempts_per_job: 1`, and the explicitly allowed `job_ids`. Each job accepts only its canonical `jobs/<job_id>/extra_001` output, and an existing native start is rejected. An external supervisor must enforce the 3600-second lifetime and must not introduce another trajectory retry. Authorization has **not** been granted or written by this preparer, and no extra visual inference has been launched.
