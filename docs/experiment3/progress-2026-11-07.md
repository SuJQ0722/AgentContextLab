## 摘要失败的真实原因

MMBrowseComp 的三次 compaction response 都是 `<｜｜DSML｜｜ calls>` 形式的 `web_search` / `web_extract` **伪工具调用文本，不是事实摘要**。虽然接口返回 `finish_reason=stop`，现有验证仅检查 stop 和非空，错误地把这些内容送入 token 测量。伪工具调用没有被执行。

实际执行 **3 次**生成：请求长度估计 1,009 → 5,656 → 6,500；测得总 prompt 为 4,447 → 4,417 → 4,443，低于共同目标 5,276 的接受区间 5,171–5,381。达到请求上限后停止，结果消息中的 “within four attempts” 只是上限描述，不能报告成实际执行四次。

证据位于：

- `outputs/experiment3/controlled-native-v2/jobs/mmbrowsecomp/q_001_r01/summary/metrics/calls.jsonl`：purpose=compaction、usage、finish。
- 同目录 `requests-responses.jsonl.gz`：按 call_id 对照三份原始 response，可见 DSML 内容。
- `summary/metrics/budget-attempts.jsonl`：三次请求长度及实测 prompt。

必要修复是强化摘要任务与归档指令的隔离，禁止执行工具，并验证生成内容确实为摘要、拒绝 DSML/工具调用输出；不能仅增加摘要长度或放宽预算。修复后需要新的版本化验证，保留当前失败与费用。

## native gate 的 false 不代表图像被修改

`pilot-gate.json` 报 `identical_prefix=false` / `identical_native_payloads=false`，原因是没有收齐三臂可验证控制记录：BC 两文本臂未运行；MM Visual 最终 timeout 的 `result.json` 不含 `control_gate`，但旁边的 `compression-control.json` 仍保存 `passed=true`、`first_actual_prompt_tokens=5276` 和 `native_identity_verified=true`。

因此这里应表述为**完整三臂验证证据不足**，不是“已证实 native pixels 被修改”。MM Summary 与 Window 保存的 prefix SHA 和 native hashes 也与该 Visual 控制记录一致；它们只是没有走到首个真实续跑请求。汇总器应区分“未知/不完整”与“已发现不一致”。

## 其他明确问题

- BC Visual 与 MM Window 是连接错误，不是已证实的 context 上限、native 超预算或模型视觉能力失败。保留未返回 usage，不能当作零费用。
- Window 第一轮测量 5,152，距接受下界仅 19 tokens；后续二分直接扩大到 23,928 字符，增加了校准调用。可以改进局部拟合效率，但不应把现有未匹配结果标成通过。
- MM Visual 成功进入真实工具 loop；3,600 秒超时与首次预算/native gate 是不同维度，应分别记录。时间上限内未完成不能包装为最终准确率结果。
- 新完整队列仍被阻断，实验 3 尚无完整 matched-baseline accuracy 表。后续修复必须保留固定题目、原生像素与预算约束，不选择性更换失败题。
