# MMBC 受控 baseline 与 VERA 超时回补

本页记录 2026-11-14 的新部署，时间均标明 UTC/北京时间。历史综合结果见 [11 月 13 日汇总](../2026-11-13/README.md)。本页的计数校正优先于历史报告中受影响的 MMBC VERA 数字；不覆盖原始日志。

## 实验设计与固定集合

按最新确认，**VERA 将原生视觉证据嵌入渲染画布；两个受控 baseline 将原生图像独立传入**。不新增第三个视觉对照臂。不声称图像 token 相同；匹配的是实际 provider 返回的首次压缩后总 prompt token，允许 ±2%。

冻结集合为 MMBC 原 100 题 × 3 repeats 中 **180/300 个非超时题次（60%）**：167 个完成并评分，13 个其他失败；另有 120/300 个超时（40%），单独补跑。集合按状态选择，不按答案是否正确选择；补跑新增完成不会自动扩大受控集合。

|每种受控方法的处理|题次|含义|
|---|---:|---|
|真实新运行|109|从同一历史前缀做一次压缩干预，随后继续推理|
|无压缩共享参考|67|原 VERA 完成且没有触发压缩，不重复运行、计费或视为两个独立测量|
|阻塞，保留缺失|4|2 个没有有效压缩后预算目标；2 个含 11 张原生图像，超过单次 10 图上限|
|合计|180|每种方法的冻结集合；不是已完成 180 个新实验|

109 个新运行前缀中，27 个当时没有原生图像，须单独分层；不能用它们支持原生图像保留的收益。实际目标预算为 8,295–24,681 tokens。源端已完成的 99 个可运行题次有 80 个正确，另 10 个源端失败不伪造参考分数。67 个无干预共享参考有 58 个正确。

阻塞题次：`mmbc_1034/r01`、`mmbc_131/r02` 缺有效目标；`mmbc_1034/r02`、`mmbc_1037/r02` 有 11 张原生图像。不得通过丢图满足上限。

**这是固定历史前缀、单次压缩干预的 continuation 实验，不是两个方法从头完整运行 100×3。** 后续不再次压缩。109 个 VERA 源轨迹中，54 个仍有原有后续压缩、55 个没有；因此本实验也不能单独证明全程压缩策略的等效性。准确率需使用实际有效配对，报告三个 repeat 的 mean ± sample std、分母及失败类别。

摘要按原文的互不重叠分段生成实质内容；窗口保留最近文本。两者均保留原生图像字节、顺序和 detail。实际 token 校准不通过的任务记为 budget-infeasible，不填充文字、不复制原文凑摘要长度、不自动重试。

摘要各源段均生成一次；合并后若超出预算，沿用实际 token 校准的前缀裁剪。因此最终摘要不保证保留每个源段，不能将“完整源分段均参与生成”表述为“压缩后信息完整保留”。每个新 continuation 的 1 小时预算包含摘要/校准与后续推理，不能直接与源 VERA 从题目开始的全程耗时比较。

初版摘要每题至多 6 个分段，但首批输出普遍短于所需预算，另有 JSON 格式拒绝。已暂停该方法新派发：25 个已派发任务保留结果与成本、在途自然结束，不重跑；84 个尚未派发任务单独冻结清单。更细分段版本仅用于这 84 个新任务，须通过第一个正式题次的真实预算和原生图校验后才恢复 16 并发，不以反复重跑同一题调参。

25 个初版任务最终为 19 个预算不足、6 个 JSON/schema 失败，0 个超时。细分版的第一个正式题次 `mmbc_097/r03` 前四段输出 2,556/929/1,019/2,303 tokens，第五段因自然引号未转义而 JSON 解析失败，后续 83 个没有派发。此题也保留已付费用量且不重跑。剩余任务改用显式纯文本事实摘要协议，移除与科学对照无关的 JSON 包装要求；仍检查完整响应、非空正文、工具调用/图像载荷、真实总 token 预算和原生图一致性。各版本分别记账，不把解析失败算作模型答错。

## 数据归属校正

核查 300 个核心题次的 470 条结果绑定后，发现 3 条历史受控结果曾误并入核心 MMBC VERA。它们的旧受控分数分别为 1、0、0。恢复真实核心状态后：

|状态|校正前|校正后|
|---|---:|---:|
|完成并评分|170|167|
|其他失败|12|13|
|超时|118|120|
|非超时集合|182|180|

校正后核心已完成轨迹 **138/167 正确**；repeat 分母 66/55/46，正确数 53/48/37；条件准确率 **82.67 ± 3.99%**。这是完成子集，不是完整 300 题次准确率，也不能排除超时选择偏差。

已核查新一轮全部 2,235 个任务的实验归属，没有把新受控任务混入核心任务。历史 120 个超时槽位关联的 792 条核心物理 attempts 与 16 条受控 attempts 分账；重试不是新 seed。原报告、结果、评分全部保留。

所有任务用 DeepSeek，沿用四渠道切换、内联图像传输和允许的 web/image 工具，预测进程不开放文件读取工具。此次新增尝试结束后不再自动重试。保留已有 attempt 记录，不重置累计次数。只有私有评分进程能读取答案。

新回补中 `mmbc_1105/r01` 的失败已定位：尚未触发压缩、没有画布，工具原生图从 8 张累积到 14 张。旧本地 guard 在“保留最近 10 图”之前拒绝了请求，后续 3 次本地拒绝均未发送 provider。此例归入本地图像策略失败，不叫 provider 超时或大画布超时；已有付费尝试不重跑。其核心图像上限逻辑与受控 baseline 的原生图完整保留约束须分别处理。

独立修复 `core-page-caps-then-recent-ten-v22` 先选历史画布 ≤5 页、recent ≤2 页，再按消息顺序保留全部来源中最近 10 张图。新增原生图很多时，较旧画布也可能被移除，因此 5/2 是上限，不保证每次都有 7 张画布。移除和保留的每张图记录 SHA、来源、原始位置及最终画布页数；不拼图、不重编码所保留像素。受控 baseline 不启用这个删除策略。真实失败请求的离线回放已验证 14→10，所保留原图 SHA 一致、请求 19.42 MiB，低于原有 32 MiB 上限。

该修复只通过独立新 epoch 接管未启动的核心补跑槽位：原 controller 停止新派发、在途自然结束；新入口逐次核查原题没有 claim/spec/attempt，沿用原已授权 attempt ordinal 与历史费用。转移额外授权数为 0，不能借迁移再跑已付费任务。新旧版本分层报告，不把版本差异全归因于模型质量。

分别保存摘要生成、预算校准、实际 agent 调用的 cached/non-cache/output/total tokens，以及端到端时间、可测调用时间和渲染时间。缺失计量为 NA，CLI 耗时不称为 provider API latency。校准请求可能预热缓存，须披露；不把源 VERA 完整轨迹耗时直接与 baseline 的后半段耗时作公平比较。共享参考不重复计费。

方法成本分析须区分“全部实际实验支出”与“摘要生成 + agent 推理”。预算校准是实验测量开销，单独报告；不能把这部分校准成本直接当作摘要方法固有劣势。即使从费用表中扣除校准，缓存预热的影响仍存在。

baseline 新日志仅含干预后的 continuation。与 VERA 比较费用时，应两边都只算干预后的轨迹，或为两 baseline 同口径补入共同前缀成本；不得将 baseline 后半段费用直接与 VERA 全轨迹费用相比。

旧受控入口在模型调用前暴露配置版本门禁和 legacy `--spec` 参数契约问题。42 条启动失败保留为 0 API 的启动诊断，不充当模型实验结果。新入口保留路由与工具检查，修复参数传递；两方法真实 Hermes 初始化检查均到达首次预算校准 SDK 边界，预检未发送外部模型请求。
