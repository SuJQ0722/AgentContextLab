# MMBC：仅发送最近10图

用户要求由“单次不超过10图”进一步明确为“只发送最近10图”。本候选在最终 HTTP 请求处按 messages 顺序、各消息 content 顺序保留最后10个 image_url 块，原生图与渲染画布一起计数。超过10时移除更早的图片块；不拼长图、不改保留图片的像素/编码/分辨率、不做按答案选择。消息中的文字、role 和工具调用身份保留。

配置为 `configs/experiment.mmbc-recent-ten-v1.json`，入口 `scripts/hermes_bounded_mmbc_recent_ten_worker_v1.py`，协议 `bounded-multimodal-recent-ten-v1`。根配置 `configs/experiment.json` 登记候选状态。该策略为独立的新协议：之前“发送全部原生视觉证据”的结论不适用于这一版本；渲染源完整性与实际请求保留哪些图片是两个独立记录。

最终发送日志记录过滤前后数量、图片原位置/SHA、保留或移除状态、原生图/画布分类、过滤前后请求体SHA。SDK之前的记录明确标为 pre-retention；实际输入以新的 final-wire 账本为准。过滤后仍检查8MiB整包限制和现有画布几何/来源约束。因此最近10图不保证所有请求体都小于8MiB，更不保证消除所有上游超时。

## 历史审计

已结束的 MMBC bounded retry 共274条轨迹。有画布的981条允许发送前检查中，总图数中位数9、90%分位12、最大21，256条（26.10%）超过10。按同轨迹同序列化请求体去重后为729种请求体，中位数8、90%分位12、最大21，158种超过10。这里的 allowed 不是 HTTP 成功，也不能等同独立题数。

最大21图实例是7张原图+14页画布；另有两条轨迹实际出现11或13张不同原生图，不能靠重复图片去重降至10。新策略会按用户要求移除更早的图片，明确记录这一行为。历史96次8MiB拒绝实际上对应16个请求体各重复6次；它们仍保留在原始费用/未知用量账本中。

详细审计：`outputs/preflight/mmbc-ten-image-audit-v1/{README.md,report.json,records.jsonl,guard-sources.json}`。
