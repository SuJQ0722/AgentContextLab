# 统一七页画布与可配置表格（2026-11-12）

本版本取代先按五轮划分recent、再分别截取history/recent的设计。未启动实验或付费模型调用。

## 当前新协议

- 所有待压缩历史按时间顺序统一排版，取最后最多7页；不足7页不填空。
- 最后最多2页为recent，保持原分辨率；其余最多5页为history，一次性0.75×下采样。分类基于页面位置，不再基于五个工具轮次。
- 新默认原页1152×2048，history发送864×1536，recent发送1152×2048；最长边保持2048。旧原页1024×2048，新面积增加12.5%。
- 保留完整源PDF，但只栅格化和编码选中的7页，避免把将要丢弃的早期页面也转成图片。排版仍然处理累计历史，尚非增量排版。
- 保护系统/任务头部与最新一个工具轮次；原生图不改变。总图数10以内先预留原生图，再recent，再history；必要时实际发送少于7张canvas。原生图本身超过10张则拒绝。
- 无损WebP内联发送，像素一致性验证；新视觉请求JSON限制3MiB。超限明确报错，不上传图床、不偷偷压低分辨率。3MiB是工程试验门槛，不是供应商上限或无超时保证。
- 独立window manifest记录源PDF哈希、总页数、丢弃前缀页数、选中页号、原始与输出尺寸/哈希和scale；registry验证完整选页顺序与下采样像素一致性。
- Hermes BC/MMBC VERA与vanilla及DSH BC接入同一renderer。RQ3保留原分辨率实验renderer；受控/信息损失也不静默套用新协议。
- 新配置在 `configs/experiment.json:visual_page_window`，冻结新任务时需复制该配置及 `visual_image_retention`。运行入口兼容旧spec字段，但实际renderer/version记录在独立manifest与统计中；历史结果不可改名为新协议结果。

## 表格尺寸

原生表格默认正文16pt、单元格18pt，列宽按内容决定，最大约页面可用宽度98%。窄表不自动撑满页面。短窄表可文字环绕；过宽或过高的表格转普通流式布局并按行/行内跨页，避免超出固定页尺寸。

新renderer独立暴露 `table_font_size=16` 和 `table_max_width_fraction=0.98`。字号不再比正文大2pt；recent保持16pt，history下采样后约12px字号。宽度上限可调（0.5–0.98），但过窄会导致换行增多、表格反而变高。当前允许表格字号16/18两档，未验证更小字号可读性。

140行的长表格仍可能跨两页甚至更多，页数上限不意味着能完整保留任意长表；只取末尾七页可能裁掉表格前部。不能宣称七页是无损上下文压缩。

## 离线尺寸比较

固定材料：一段已有BC recent PDF提取文本，加开发fixture中的crop/zoom/image search与140行表格。它是布局/体积探针，不是原轨迹重放，不是benchmark准确率评测。以下均为单次离线测量，表格字号16pt；JSON只有messages，不包括完整SDK工具schema等开销。

|原页尺寸|源PDF页数|保留页数|WebP总字节|messages JSON字节|渲染秒|几何token估计|
|---|---:|---:|---:|---:|---:|---:|
|1024×2048|8|7|1,309,234|1,748,174|2.74|52,704|
|1152×2048|7|7|1,678,914|2,241,078|2.45|58,964|
|1280×2048|7|7|1,671,788|2,231,582|2.44|65,732|

宽度1024的版本已丢弃一页，所以其字节数更低不能视为同等内容更高效。无损编码大小受内容/换行影响，不严格随像素单调增长。token列为现有几何启发式，非provider实测或计费；渲染秒不是API延迟。

选择1152×2048作为当前默认：本探针能多保留一页内容，相比1280图像面积及几何估计更低；没有证据证明更大的画布接近供应商安全极限。不能把单次离线探针当作全面性能结论。
